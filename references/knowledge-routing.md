# 知识路由

只在需要决定“读取什么、产出写到哪里、是否晋升为规则”时阅读本文件。

## 三类知识

### 事实

用户亲自确认、简历或可信原始材料能够支持的内容，例如任职时间、职责边界、产品方案、指标定义和结果。事实只进入 Profile 或对应流程的事实区。

### 答案

为了表达事实而组织的口述版本，包括自我介绍、STAR 故事、项目深挖答案和公司定制回答。

- 跨公司围绕同一经历复用：Experience Cards。
- 针对当前公司、岗位或轮次改写：Processes。
- 简历成品：Resumes。

### 教训与规则

- 从某场面试得到、仍与用户背景相关：Reusable Learnings。
- 可能对其他 PM 候选人也有价值：Rule Promotion Queue。
- 完成脱敏、验证和授权：才进入公开 skill 的 references、templates 或 SKILL.md。

## 写入优先级

一次任务可能更新多个位置，但必须各司其职：

1. 原始输入进入 Inbox 或单场复盘的原始材料区。
2. 流程状态更新到 Process，以及 Current Plan 中的流程清单。
3. 具体答案更新到 Process Q&A 或 Experience Card。
4. 抽象教训更新到 Reusable Learnings。
5. 通用规则候选只进入 Rule Promotion Queue，不自动发布。

## 冲突处理

- Profile 与口述答案冲突：以已确认事实为准，标记答案待修订。
- 两份资料都声称是事实源：保留两者，展示差异并请用户确认；不要静默覆盖。
- 同一公司和岗位出现多个流程：依据年份或批次区分，避免混合。
- 无法确定归档位置：先保存为结构化草稿，并列出候选位置。
- 旧聊天、旧简历或旧答案与最新版事实源冲突：不得以聊天更近或表述更完整为由覆盖事实源；记录旧口径被哪条已确认事实替代。
